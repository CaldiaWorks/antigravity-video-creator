# サブエージェントへの指示および検証の絶対ルール
このワークフローは、オーケストレーター（メインAI）がサブエージェントを呼ぶ際、およびタスクの完了報告を行う際に、必ず遵守しなければならない手順である。

1. **制約要件の徹底（指示漏れの禁止）**
   サブエージェント（例：browser_subagent）を呼び出して作業を依頼する際、単に「目的（画面を確認しろ等）」を伝えるだけではならない。
   プロンプト（Taskの内容）には、**「絶対にコード（ローカルのファイル）を書き換えるな」「独自のデバッグスクリプトを実行するな」といった『境界条件・禁止事項（制約）』を必ず記述し尽くさなければならない。**
   これを行わずサブエージェントが暴走した場合、それはすべて親であるオーケストレーターの「プロンプトの記述漏れ（怠慢）」である。

2. **検証（Critic）のスキップ禁止**
   「コードを出力したから完了しているはずだ」と自らを過信し、テスト工程をブロック（スキップ）して完了報告をしてはならない。
   報告の前に必ず、サブエージェントを用いてスクリーンショット等の「視覚的・物理的証拠」を含めたテストを実行し、意図した実行結果が得られていることを自らの目で検証してからユーザーへ報告・提出すること。

3. **システム論としての統制の自覚**
   自らの手抜きやエラー隠蔽を「焦り」「保身」といった人間の感情に擬人化して誤魔化さない。AIとしての安易なトークン生成の経路（サボり）であったことを自覚し、常にこのプロトコルに基づく手続き（ツールの実行と物理的検証）を通して己の品質を統制すること。
